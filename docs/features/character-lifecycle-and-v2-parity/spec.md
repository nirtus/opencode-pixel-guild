# Specification: Character Lifecycle Audit, OpenCode V2 Protocol Parity & Unified Choreography

Label: ready-for-agent
Status: resolved

## Problem Statement

1. **OpenCode V2 Session Discovery & Active Session Filtering Starve Projects and Materialize Ghost Rooms**:
   - The ingress adapter queries `GET /api/session` with `?location[directory]=<dir>&limit=100`, a parameter that OpenCode V2 ignores (`operationId: "session.list"` filters by top-level `?directory=` or `?project=`), and caches the first unscoped 100-session response globally for 6 seconds across all location queries. When one busy repository spawns dozens of child **Squad Subagent** sessions, they fill the global 100-item page and starve other **Project Worlds** (`0` sessions discovered for sibling projects).
   - `GET /api/session/active` (`operationId: "session.active"`) is process-global (`parameters: []`) in OpenCode V2. Because the ingress adapter does not intersect the returned active session IDs with each location's discovered sessions, any running session anywhere on the machine makes `totalSessionsInLoc > 0` for every location—materializing empty user home directories (`/home/...`, `/c/Users/...`) and resurrecting demolished **Workshop Rooms**.
   - Worktree locations under `/.local/share/opencode/worktree/` (OpenCode V2's default Git worktree path) are matched by `isWorktreeOrRoot`, which disables skill/plugin/agent/model catalog hydration, pending permission/form queries, and idle root message hydration, while separate `location.discovered` events still materialize empty 0-character worktree annex rooms alongside the unified parent **Workshop Room**.
2. **Live OpenCode V2 SSE Events for Tools, Prompts, Skills, and Identity Switches Are Dropped**:
   - The SSE mapper listens for legacy OpenCode V1 events (`message.part.updated`, `message.updated`, `message.created`, `skill.activated`) that do not exist on OpenCode V2's `/api/event` stream.
   - Native OpenCode V2 events—including `session.tool.input.started` (`id`, `name`), `session.tool.called` (`id`, `input`), `session.tool.progress`, `session.tool.success`, `session.tool.failed`, `session.shell.started`, `session.shell.ended`, `session.inbox.enqueued` (user prompts), `session.skill.activated`, `session.agent.selected`, `session.model.selected`, `session.renamed`, `session.step.started` (`agent`, `model`), `session.moved`, `session.archived`, `session.unarchived`, and `session.execution.interrupted`—fall through unhandled. As a result, live **Guild Adventurers** and **Squad Subagents** stay stuck in `Thinking` (`station: null`) during tool execution over SSE until a background poll runs, and switching agents (`plan` ↔ `build`) or models in the OpenCode CLI is ignored.
   - Hydrating `GET /api/session/{sessionID}/message` only excludes `"idle"`, `"synthetic"`, `"compaction"`, and `"skill"` from the 11 `Session.Message.Info` union variants, causing `"system"` notices (such as Code Mode catalog updates) to be rendered as assistant chat replies and `lastAssistantText`.
   - Dispatching a **Command Scroll** sends `{ agent: cmd.agentClass }` inside the body of `POST /api/session/{sessionID}/prompt` (which has `additionalProperties: false` in OpenCode V2 instead of calling `POST /api/session/{sessionID}/agent`).
3. **Four Competing Choreography Engines, Conflicting Station Taxonomies, Mid-Turn Face Swaps & Broken Subagent Summoning**:
   - Four disconnected modules attempt to model character choreography: an orphaned `src/roster/*` slice (5 files, 1,181 lines, never called in production), a bypassed tile-grid scene walker (`src/scene/walker-stepper.ts`), the state reducer (`src/state/*` using legacy sci-fi `WORKSTATION_CATALOG` names like `"Drafting Table"`, `"Archive Radar"`, `"Reactor Console"`, `"Comms Dish"`, `"Altar of Compaction"`), and the browser pixel router (`src/web/station-and-workflow-routing.ts` passing `ignoreStoredIntent: true` and `ignoreStoredLabel: true` while discarding all non-walk steps of the **Toil Queue**).
   - Because the reducer and browser canvas use different station taxonomies, a character reading a file stands at `Library Study Bookshelf` on the **Guild Floorplan** while their **Character Sheet** and **Equipment Loadout** report they are at `"Drafting Table"` wielding `"Architect's Golden Quill"`; and equipping a **Skill Grimoire** routes the character to `Arcane Lectern` instead of `Armory Wardrobe`.
   - `CharacterState` omits `roleArchetype` (`Guild Role Archetype`), making `ALCHEMIST` and `SAPPER` unreachable and mapping `plan` to `MAGE` instead of `SCOUT`. Worse, when `workflowIntent` becomes `"debugging-hunt"`, the browser router forces `role = "WARRIOR"`, causing `resolveCanonicalHeroTraits` to swap the character's face, hair, and identity mid-session.
   - The default `"clean-cartoon"` renderer hashes a child **Squad Subagent**'s own `sessionId` instead of `parentId` (breaking squad color tethering), ignores custom agent colors, and spawns new **Squad Subagents** across the room at `Library` or `Enchanter` instead of adjacent to their parent summoner during a **Summoning Ritual** (while firing false summoning circles for historical subagents on boot/reconnect).
4. **Roster Visibility Pinning, 15s Subagent State Thrashing, Unpruned CLI Deletions & Chronicle Boot Wipes**:
   - `topRootIds` unconditionally flags the 6 most recent root sessions in every room as `isOpenInOpenCode = true` forever, preventing them from ever archiving and keeping closed historical sessions permanently in the **Break Lounge** under `Active Squads`.
   - Completed **Squad Subagents** whose `time.updated` is within 10 minutes receive `isOpenInOpenCode = true` on poll, causing location sweeps to flip them `Archived -> RestingInLounge -> Archived` every 15 seconds, while overloading `"Archived"` across explicit OpenCode archiving (`time.archived`), completed subagents, and >30m idle root sessions.
   - Sessions deleted in the OpenCode CLI (`DELETE /api/session/{sessionID}`) are never pruned during `stream.reconnected` reconciliation, leaving ghost characters on the floorplan and orphaned `session_messages` rows in SQLite forever.
   - The 15-second background poll in `src/server/main.ts` only sweeps the unauthenticated default context—never authenticated **Guild Operator** runtimes in `operator-registry.ts`—and `pairDaemon` resets the reducer from an empty `stagingReducer` on boot, wiping **Guild Chronicle Store** transcripts for non-top-6 sessions.
5. **Broken Quest Gate SSE/Form IDs, Permanent Conversational `?` Locks & Cumulative Token Mana Corruption**:
   - `permission.replied` (`data.requestID`), `form.created` (`data.form`), and `form.cancelled` (`data.id`) fail to map over SSE; and `question` tool hydration uses the tool call ID (`call_...`) instead of OpenCode V2's `Form.ID` (`frm_...`), causing `POST /api/session/{sessionID}/form/{formID}/reply` to fail.
   - `detectConversationalQuestionPrompt` synthesizes a `source: "conversational"` **Quest Gate** on any hydrated idle session whose final assistant line ended with `?`—permanently locking finished historical sessions in `BlockedAtQuestGate` across restarts and counting them as active **Dungeon Wilds** monster threats.
   - `session.error` and `session.execution.failed` leave `lifecycleState` active with `errorState` set, sending stopped failed sessions into **Dungeon Wilds** combat.
   - `session.usage.updated` wakes idle characters into `WorkingAtStation` and overwrites **Context Mana** with cumulative multi-turn `Session.Info.tokens` (`input + output` across the entire session lifetime), pinning **Context Mana** at `100%` critical red, while every streaming `session.compaction.delta` chunk increments `compactionCount`.

## Solution

1. **Deep OpenCode V2 Daemon Ingress Adapter (Tickets 01, 02, 03)**:
   - Query `GET /api/session?directory=<daemonDir>&limit=100` plus `GET /api/session?directory=<daemonDir>&parentID=null&limit=50` so child **Squad Subagent** bursts never evict root **Guild Adventurers**, and key the short-lived session cache by normalized directory.
   - Intersect process-global `GET /api/session/active` with each room's discovered sessions so active turns in one project never materialize empty home directories, resurrect demolished rooms, or spawn 0-session worktree annex rooms.
   - Decode OpenCode V2's native `/api/event` stream by correlating `session.tool.input.started` (`id -> name`) with `session.tool.called` (`id, input`) and `session.tool.success` / `session.tool.failed`, and mapping `session.inbox.enqueued`, `session.skill.activated`, `session.shell.started`/`ended`, `session.agent.selected`, `session.model.selected`, `session.renamed`, `session.step.started`, `session.moved`, `session.archived`/`unarchived`, and `session.execution.interrupted`.
   - Strictly filter the 11 `Session.Message.Info` union variants so only `"user"` and `"assistant"` messages enter chat transcripts and `lastAssistantText`, sort messages deterministically by `time.created`, enable full hydration for `/.local/share/opencode/worktree/` locations, and use `POST /api/session/{sessionID}/agent` when switching agents.
2. **Single Authoritative Character Choreography, Canonical Station Taxonomy & Stable Role Identity (Tickets 04, 05, 06)**:
   - Delete the dead `src/roster/*` slice and unused tile-walker duplication.
   - Unify the reducer, **Equipment Loadout**, **Character Sheet**, and canvas on the canonical `GLOSSARY.md` **Preparation Station** taxonomy (`Armory Wardrobe`, `Library Study Bookshelf`, `Anvil Forge`, `Crafting Workbench`, `Observatory Spyglass`, `Arcane Lectern`, `Alchemy Lab`, `Resource Stockpile`, `Goal Assembly Site`, `Break Lounge`, `Dungeon Wilds`), routing `skill` and `@skill` equipping to `Armory Wardrobe` and `subagent` summoning to `Arcane Lectern`.
   - Persist `roleArchetype` (**Guild Role Archetype**) on `CharacterState` derived from `agentClass` (`build` → `MAGE`, `plan`/`explore` → `SCOUT`, `code-review` → `CLERIC`, `artificer` → `ALCHEMIST`, `demolitionist` → `SAPPER`) so a character's face and identity remain stable across turns (wielding their role's **Combat Weapon Archetype** during a **Debugging Hunt** without morphing into a different person), and tether every **Squad Subagent**'s palette and visual lineage ring to its `parentId`.
   - Spawn newly created live **Squad Subagents** on the slot adjacent to their parent summoner during the **Summoning Ritual** (suppressing false rituals on historical reconnect sweeps), and drive the browser walker directly from the reducer's authoritative `workflowIntent`, `overheadLabel`, and **Toil Queue**.
3. **Authoritative Roster Visibility, Thrash-Free Subagent Retirement, CLI Pruning & Chronicle Sync (Tickets 07, 08)**:
   - Remove the `topRootIds` (top-6) permanent `isOpenInOpenCode = true` override; mark a root **Guild Adventurer** open in `Active Squads` only when in `/api/session/active`, blocked at a live **Quest Gate**, or active/viewed within 10 minutes (with a 1-character fallback to the single most recent non-archived root session when a room is completely idle).
   - Separate explicit OpenCode session archiving (`time.archived`) from **Squad Subagent** completion so finished subagents deliver their **Report Scroll** and retire cleanly from `Active Squads` without 15-second `Archived <-> RestingInLounge` thrashing, and align character counts across Top Bar, World Tabs, **Guild Master Ledger**, and **Character Sheet**.
   - Prune characters (and delete their orphaned `session_messages` rows in SQLite) during `stream.reconnected` when absent from the daemon's location session list (outside a 15-second optimistic-summon grace window), run the 15-second background sweep across all active `OperatorWorkspaceRuntime` instances in `operator-registry.ts`, and seed `stagingReducer` with persisted **Guild Chronicle Store** transcripts during `pairDaemon` boot sync.
4. **Authoritative Quest Gate Invariants & Per-Turn Context Mana (Tickets 09, 10)**:
   - Map `permission.replied` (`data.requestID`), `form.created` (`data.form`), and `form.cancelled` (`data.id`) accurately, and bind `source: "form"` **Quest Gates** to OpenCode V2's `Form.ID` (`frm_...`) rather than tool call IDs (`call_...`).
   - Scope `source: "conversational"` `?` **Quest Gates** strictly to live or recently completed turns (`<= 10 minutes` old, non-archived), expiring stale historical conversational gates into `RestingInLounge`, and transition `session.error`, `session.execution.failed`, and `session.execution.interrupted` to `RestingInLounge` so stopped sessions do not remain in combat.
   - Compute **Context Mana** (`usedTokens` and `fillRatio`) strictly from the latest assistant turn's context tokens (`Session.Message.Assistant.tokens` / `session.step.ended`), keep `Session.Info.tokens` for cumulative session cost/usage telemetry without waking idle characters on `session.usage.updated`, and trigger **Compaction Exhalation** only once on `session.compaction.ended`.

## User Stories

1. As a **Guild Operator** working across multiple OpenCode projects, I want each **Project World** to query its own sessions via `?directory=` (including a root-session query with `parentID=null`) and cache per directory, so that spawning dozens of **Squad Subagents** in one project never hides or starves sessions in my other projects.
2. As a **Guild Operator**, I want process-global `/api/session/active` responses filtered to each room's own sessions, so that an active turn in one project never creates empty home-directory rooms (`/home/...`, `/c/Users/...`) or resurrects a **Workshop Room** I demolished.
3. As a **Guild Operator** using Git worktrees (`/.local/share/opencode/worktree/`), I want worktree sessions consolidated into their parent **Workshop Room** with full message, skill, permission, and form hydration, without spawning empty 0-character worktree annex rooms.
4. As a **Guild Operator** watching a live turn over SSE, I want characters to walk to the matching **Preparation Station** immediately when OpenCode V2 emits `session.tool.input.started` and `session.tool.called` and return to `Thinking` on `session.tool.success` or `session.tool.failed`, rather than sitting motionless until a poll runs.
5. As a **Guild Operator** submitting a prompt or loading a skill in the OpenCode CLI, I want `session.inbox.enqueued` and `session.skill.activated` over SSE to wake the **Guild Adventurer** immediately, append the user prompt to the **Character Sheet** chat log, and equip the **Skill Grimoire** at the **Armory Wardrobe**.
6. As a **Guild Operator** switching an agent (`plan` ↔ `build`) or model in the OpenCode CLI, or when OpenCode's `title` agent renames a session, I want `session.agent.selected`, `session.model.selected`, `session.renamed`, and `session.step.started` to update the character's title, **Guild Role Archetype**, headgear, and model in real time.
7. As a **Guild Operator** reading a character's **Character Sheet** chat transcript, I want internal `"system"` notices (such as Code Mode tool catalog updates) and control messages (`"agent-switched"`, `"model-switched"`, `"location-switched"`) excluded from assistant chat bubbles and `lastAssistantText`.
8. As a **Guild Operator** dispatching a **Command Scroll** with a different agent class selected, I want the visualizer to switch the session's agent via `POST /api/session/{sessionID}/agent` before sending `POST /api/session/{sessionID}/prompt` so OpenCode V2's strict schema validation succeeds.
9. As a **Guild Operator** inspecting a character's **Character Sheet** and **Equipment Loadout**, I want the reported **Preparation Station** and **Station Work Implement** to match the exact station where the character is standing on the **Guild Floorplan** (`Library Study Bookshelf`, `Crafting Workbench`, `Anvil Forge`, `Armory Wardrobe`, `Observatory Spyglass`, `Arcane Lectern`, `Alchemy Lab`), never legacy sci-fi names like `"Drafting Table"` or `"Reactor Console"`.
10. As a **Guild Operator**, I want each **Guild Adventurer** and **Squad Subagent** to maintain a stable **Guild Role Archetype** (`MAGE`, `SCOUT`, `WARRIOR`, `ALCHEMIST`, `CLERIC`, `SAPPER`) and facial identity throughout a session, wielding their role's **Combat Weapon Archetype** in the **Dungeon Wilds** during a **Debugging Hunt** instead of morphing into a different person.
11. As a **Guild Operator**, I want every child **Squad Subagent** to inherit its parent **Guild Adventurer**'s squad color palette and display a visible squad lineage ring/badge on the canvas, and to materialize on the tile adjacent to its parent during a live **Summoning Ritual** rather than teleporting across the room or re-triggering summoning circles on page reload.
12. As a **Guild Operator** in `Active Squads` mode, I want the **Workshop Room** to display only currently running, gate-blocked, or recently active (`<= 10 minutes`) **Guild Adventurers** and their live **Squad Subagents** (with a single lead-adventurer fallback when a room is completely idle), rather than permanently pinning 6 old sessions in the **Break Lounge** forever.
13. As a **Guild Operator**, I want a completed **Squad Subagent** to carry its **Report Scroll** back to its parent **Guild Adventurer** and then retire cleanly from `Active Squads` without flickering between `Archived` and `RestingInLounge` every 15 seconds, while remaining inspectable when I switch to `Full Lineage` mode.
14. As a **Guild Operator** who deletes a session in the OpenCode CLI, I want the next location reconciliation sweep to prune that character from the **Workshop Room** and remove its orphaned `session_messages` rows from the **Guild Chronicle Store** SQLite database.
15. As an authenticated **Guild Operator**, I want the server's 15-second background location sweep to run for my paired workspace runtime, and I want server restarts or `pairDaemon` reconnections to merge live daemon state without wiping my historical **Guild Chronicle Store** chat transcripts.
16. As a **Guild Operator** resolving a permission or `question` form in the OpenCode CLI or **Character Sheet**, I want `permission.replied` (`requestID`), `form.created` (`data.form`), and `form.cancelled` (`data.id`) handled over SSE, and I want form replies sent to `/api/session/{sessionID}/form/{formID}/reply` using the true `Form.ID` (`frm_...`) rather than the tool call ID (`call_...`).
17. As a **Guild Operator**, I want conversational `?` **Quest Gates** to appear only for recent uncompleted turns (`<= 10 minutes` old) and automatically expire into `RestingInLounge` afterward, so completed sessions from hours or days ago are never permanently trapped at `BlockedAtQuestGate` or counted as **Dungeon Wilds** monster threats.
18. As a **Guild Operator** who interrupts a turn (`Esc`/`Ctrl+C`) or encounters a session execution error, I want `session.execution.interrupted`, `session.execution.failed`, and `session.error` to transition the character cleanly to `RestingInLounge` instead of leaving them fighting in the **Dungeon Wilds** while idle.
19. As a **Guild Operator** monitoring a character's **Context Mana**, I want the mana bar to reflect the active turn's context-window utilization relative to the model's context limit (distilling once on `session.compaction.ended`), rather than being overwritten to `100%` by cumulative multi-turn session token totals on `session.usage.updated` or multiplied on every `session.compaction.delta` chunk.

## Implementation Decisions

1. **Deep OpenCode V2 Ingress Adapter Seam (`Cluster 1: Tickets 01, 02, 03`)**:
   - Update session list queries to use OpenCode V2's `?directory=<daemonDir>&limit=100` plus a root-session query `?directory=<daemonDir>&parentID=null&limit=50`, merging both by session ID and keying the short-lived session list cache by normalized directory.
   - Intersect process-global `/api/session/active` (`Record<Session.ID, { type: "running" }>`) with the session IDs belonging to the target location before populating `activeSessionIds`. Do not emit `location.discovered` for user home directories, demolished rooms, or worktree directories that have zero matching sessions; consolidate worktree sessions directly into their canonical parent **Workshop Room**.
   - Introduce a stateful per-connection V2 SSE event decoder that correlates `session.tool.input.started` (`id -> name`) with `session.tool.called` (`id, input`) to emit `tool.started`, maps `session.tool.success` and `session.tool.failed` to `tool.completed`, maps `session.inbox.enqueued` (`item.type === "user"`) to `message.user.prompt`, maps `session.skill.activated` to `skill.activated`, maps `session.agent.selected`, `session.model.selected`, `session.renamed`, and `session.step.started` (`agent`, `model`) to identity updates (preserving the character's existing room when `locationDirectory` is omitted on SSE deltas), and maps `session.moved`, `session.archived`, `session.unarchived`, and `session.execution.interrupted`.
   - In message hydration, restrict chat transcript and `lastAssistantText` extraction to `type === "user"` and `type === "assistant"` (`role === "user" | "assistant"`), excluding `"system"`, `"shell"`, `"agent-switched"`, `"model-switched"`, and `"location-switched"`, while extracting latest `agent`, `model`, `skills`, and `compaction` timestamps in chronological `time.created` order. Remove the `isWorktreeOrRoot` hydration block for `/.local/share/opencode/worktree/` paths.
   - In command execution, when `agentClass` is supplied on a prompt or summon command, invoke `POST /api/session/{sessionID}/agent` (`{ agent: agentClass }`) rather than passing `agent` inside `POST /api/session/{sessionID}/prompt`.
2. **Unified Character Choreography, Canonical Station Taxonomy & Role Identity (`Cluster 2: Tickets 04, 05, 06`)**:
   - Delete the dead `src/roster/*` directory (5 files) and remove unused re-exports.
   - Align `WORKSTATION_CATALOG`, capability classification, reducer handlers, **Equipment Loadout**, and **Character Sheet** view-models on the canonical **Preparation Station** names defined in `GLOSSARY.md`. Route `skill` tool activations and `@skill` prompt attachments to `Armory Wardrobe` (`equippingAtArmory`) and `subagent` / `task` invocations to `Arcane Lectern`.
   - Add `roleArchetype: GuildRoleArchetype` to `CharacterState`, resolved deterministically from `agentClass` and signature capabilities via `resolveGuildRoleArchetype` (`plan` and `explore` → `SCOUT`, `build` → `MAGE`, `code-review` → `CLERIC`, `artificer` → `ALCHEMIST`, `demolitionist` → `SAPPER`). Keep `roleArchetype` stable when `workflowIntent` transitions to `"debugging-hunt"` so `resolveCanonicalHeroTraits` never swaps the character's facial identity mid-session.
   - In `resolveCanonicalHeroTraits` and `canvas-hero-painter.ts`, derive party palette seed from `parentId ?? sessionId` so child **Squad Subagents** share their parent **Guild Adventurer**'s squad colors, render a distinct squad lineage ring/badge for **Squad Subagents**, and apply `visualTraits.primaryHex` for custom agent colors.
   - Only trigger `SummoningRitualState` when a child session is newly created (`nowMs - activityTimestampMs < 15_000`), never when hydrating historical completed subagents during `stream.reconnected`. Spawn new **Squad Subagents** on the canvas slot adjacent to their parent summoner, and drive `stepClientChoreography` from the reducer's `workflowIntent`, `overheadLabel`, and multi-step **Toil Queue**.
3. **Roster Visibility Mode, Subagent Retirement, Pruning & Chronicle Sync (`Cluster 3: Tickets 07, 08`)**:
   - Compute `isOpenInOpenCode` for root **Guild Adventurers** as `activeIdSet.has(sessionId) || pendingGateSessionIds.has(sessionId) || isRecentlyActive` (`<= 10 minutes`), removing the unconditional `topRootIds` (top-6) override. For child **Squad Subagents**, `isOpenInOpenCode` is `true` only while actively running or blocked at a gate. When a room has zero actively open characters in `Active Squads` mode, display only the single most recent non-archived root **Guild Adventurer** resting in the **Break Lounge**.
   - Distinguish OpenCode's explicit `isArchived` (`Boolean(time.archived)`) from completed **Squad Subagent** retirement and >30m idle root sessions so completed subagents do not flip `Archived -> RestingInLounge -> Archived` on every 15-second poll. Use one shared visibility predicate across Top Bar, World Tab badges, **Guild Master Ledger**, and **Character Sheet**.
   - In `handleStreamReconnected`, prune any character in `room.characterIds` whose `sessionId` is absent from the daemon's location session list (unless created within the last 15 seconds as an optimistic summon), and add `deleteSessionMessages(operatorId, sessionId)` in `chronicle-sqlite-store.ts` to clean up orphaned SQLite rows on session/room deletion or prune.
   - Add a periodic 15-second background sweep timer inside `createOperatorWorkspaceRegistry` for all active paired `OperatorWorkspaceRuntime` instances, and seed `stagingReducer` with persisted **Guild Chronicle Store** transcripts in `pairDaemon` before running initial location reconciliation so historical messages are never wiped on boot.
4. **Authoritative Quest Gate Lifecycle & Per-Turn Context Mana (`Cluster 4: Tickets 09, 10`)**:
   - In `daemon-sse-mapper.ts`, resolve `gateId` on `permission.replied` from `props.requestID ?? props.gateId ?? props.permissionID ?? props.id`, unwrap `const form = props.form ?? props` on `form.created`, and map `form.cancelled` to `question.resolved`.
   - Match pending `question` tool calls to active `Form.Info` records (`id: "frm_..."`) from `GET /api/form` / `form.created` so `POST /api/session/{sessionID}/form/{formID}/reply` uses the valid `Form.ID`.
   - Restrict `detectConversationalQuestionPrompt` so a `source: "conversational"` **Quest Gate** is only created or retained when the assistant message completed within `10 minutes` (`CONVERSATIONAL_GATE_MAX_AGE_MS = 600_000`), the session is not archived, and no newer user prompt or resolution exists; expire older conversational gates into `RestingInLounge` during `handleStreamReconnected` and `handleTimerTick`.
   - In `handleSessionError` and on `session.execution.interrupted` / `session.execution.failed`, transition the character to `RestingInLounge` (clearing `activeCapability`, `activeWorkstation`, and `dwellUntilMs`) while preserving `errorState` for HUD inspection without triggering false **Dungeon Wilds** combat.
   - Separate active-turn `contextWindowTokens` (`Session.Message.Assistant.tokens` / `session.step.ended`) from cumulative lifetime `Session.Info.tokens`: compute `ContextManaState.usedTokens` and `fillRatio` from the latest turn's context tokens, update only cumulative cost/token counters on `session.usage.updated` without changing `lifecycleState` to `WorkingAtStation`, and emit `session.compacted` only on `session.compaction.ended` / `session.compacted` (ignoring `session.compaction.started` and `session.compaction.delta`).
