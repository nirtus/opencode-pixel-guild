# Wayfinder Map: Public Asset Privacy Remediation & Synthetic Screenshot Pipeline

Label: wayfinder:map

## Destination

Deliver a zero-leak public repository and permanently guarded documentation-asset pipeline where:
1. All leaked real-project screenshots are immediately quarantined from `assets/images/` and purged from Git history across all branches (`main`, `development`) and tags (`v0.8.0`, `v0.2.0`, `v0.2.1`), accompanied by an external GitHub/community takedown audit.
2. Every remaining static image in `assets/images/` is audited for real project names, hostnames, paths, or session content.
3. Every **Public Documentation Asset** under `assets/images/` is reproducibly generated from 100% synthetic fictional fixtures via an offline **Synthetic Documentation Showcase** (`?demo=docs-showcase&scene=<id>` + `npm run docs:screenshots`), consolidating `README.md` into a curated, high-signal set of ~12–16 canonical scenes.
4. `assets/images/` is structurally protected against future leaks by four enforcement layers: a SHA-256 **Public Asset Manifest** (`assets/images/manifest.json`) enforced in `tests/00-architecture-invariants.test.ts`, automated PNG metadata stripping + OCR hygiene scanning inside the Dockerized capture pipeline, a zero-dependency local `.githooks/pre-commit` guard (`npm run hooks:install`), and explicit `AGENTS.md` / `docs/agents/container-deployment.md` / `GLOSSARY.md` boundaries separating **Public Documentation Assets** (`assets/images/`) from gitignored **Development Verification Captures** (`docs/images/`).

## Notes

- **Domain**: Public repository privacy remediation, Git history sanitization, offline synthetic showcase rendering, and cryptographic/OCR asset provenance governance.
- **Canonical Vocabulary**: See root `./GLOSSARY.md` (`### Documentation & Public Asset Governance` — **Public Documentation Asset**, **Development Verification Capture**, **Synthetic Documentation Showcase**, **Public Asset Manifest**; plus **Intro Demo Director** and **Demo Guild Simulator**).
- **Skills Every Session Should Consult**: `grilling` and `domain-modeling` for decision tickets; `research` for AFK investigation tickets; `verification-before-completion` before resolving any ticket.
- **Privacy Rule for All Tracker Files**: NEVER transcribe real project names, real machine names, personal usernames, private paths, or private chat excerpts into any ticket, map, spec, or commit message. Record only filenames, `CLEAN` / `LEAKED` verdicts, and generic UI regions (for example, `Worlds bar`, `north wall banner`, `underfoot nameplate`, `Assembly Commit Ledger`, `Hero Chat`, `top-bar machine strip`).
- **Execution Override**: This map carries urgent operational `task` tickets ([Immediate Containment & Quarantine of Leaked Public Documentation Assets](./issues/01-immediate-containment-and-quarantine-of-leaked-images.md) and [Purge docs/images/ From Git History, Force-Push Rewritten Branches/Tags & Execute External Exposure Takedown](./issues/06-git-history-purge-tag-rewrite-and-external-exposure-takedown.md)) directly in the map because containment and history purge are time-critical prerequisites; design/architecture tickets (`04`, `05`) produce decisions/specifications before graduating implementation work out of fog.
- **Standing Repo Rules**: Work strictly inside the project root (`./`). Never create git worktrees or write files to `/tmp` or `/tmp/opencode`. Never delete `./data/` or modify live operator profiles. Keep every `src/` file `<= 400` lines and preserve zero external npm dependencies in `package.json`.

## Out of scope

- **Manual pixel redaction or blurring of live-captured screenshots**: Ruled out because subtle leaks in chat transcripts, tool outputs, crests, or file paths are error-prone and non-reproducible; all **Public Documentation Assets** must be generated strictly from synthetic fixtures.
- **Adding external npm dependencies (Husky, lint-staged, Playwright/Puppeteer packages) to `package.json`**: Ruled out to preserve the project's zero-dependency Node.js 22 runtime; pre-commit hooks use native `.githooks/pre-commit` with Node 22, and browser/OCR tooling runs inside Docker.
- **Removing or restricting local gitignored `docs/images/` development workflow or modifying `./data/`**: Ephemeral **Development Verification Captures** remain available locally in gitignored `docs/images/` for developer verification and never touch live `./data/` profiles.
